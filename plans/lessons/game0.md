**Phase C lessons-learned (one paragraph, for the next session's context):**

The ECS's three-trait stack (`QueryData` for data shape, `QueryFilter` for skip predicates, `SystemParam` for system-side dispatch) settled into a clean separation by making each trait carry its own `Fetch<'w>` GAT and resolving access through `ComponentId`-keyed handles, never raw `TypeId`. The load-bearing decision was making `Query<&mut T>` go through an audited `unsafe` split-borrow in `query::fetch::split_storages` rather than per-component `RefCell` — the unsafe is contained to one module, paid once per query construction, and pre-validated by `check_no_alias`; everything downstream (per-entity `fetch`, the `FunctionSystem` arity dispatch) is fully safe. Two design choices to remember when Phase F lands: (1) the `Join` engine collects the smallest required storage's entities into a `Vec<EntityId>` upfront and drops its borrow before any typed `Fetch` is built — this is what lets `Query<&mut T>` coexist with the join without aliasing, and the renderer's `Query<(&Transform, &MeshHandle)>` benefits from the same pattern. (2) Per-system access conflict checking now happens at `Schedule::add_system` registration (which is why `add_system` takes `&mut World`); when Phase D wires the `App`'s schedule, it must thread the world through. The `change_detection` substrate (Mut-pointer + tick bumps) has a real consumer for the first time in C9.4: `Query<WriteOnly<T>>` shares the iteration's tick across all writes in one call so a single system run produces a coherent change-tick window for downstream observers — Phase G's controller writes will land cleanly through `world.changed_since`.
